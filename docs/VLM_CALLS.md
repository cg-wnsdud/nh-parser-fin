# VLM 호출 상세 — 무엇을, 어떻게 물어보는가

main 브랜치(3d3dacb, PR #2 병합 후) 기준입니다. 파이프라인이 VLM에 보내는 **모든 호출**에 대해
언제 부르는지, 이미지·텍스트로 무엇을 넣는지, 프롬프트 원문, 받는 값, 받은 뒤 코드가 하는 일을
적습니다. 전체 흐름 안에서의 위치는 [PIPELINE_WALKTHROUGH.md](PIPELINE_WALKTHROUGH.md)를 보세요.

## 0. 요약

기본값(환경변수 미지정)에서 실제로 쓰이는 호출은 **11종**입니다. 3·6·7번은 다른 호출이
실패하거나 비었을 때만 쓰는 대체 경로입니다.

| # | 단계 (`schema_name`) | 언제 | 단위 | 이미지 | 텍스트 입력 |
|---|---|---|---|---|---|
| 1 | 문서 분류 `ad_classification` | 항상 | 문서당 1회 | 첫 페이지 | 파일명 |
| 2 | 페이지 맥락·소유권 `parser_v2_page_ownership` | 항상 | 페이지당 1회, 긴 페이지는 밴드 2~4회 | 페이지 + ID 박스 | Region ID·bbox·Paddle 분류·**OCR 문구** |
| 3 | 페이지 Reader `parser_v2_page_reading` | 항상 | 밴드 안에서 최대 20 Region씩 | 원본 페이지 + ID 박스 페이지 | Region ID·bbox만 (문구 없음) |
| 4 | crop Reader `parser_v2_region_reading` | 3에서 빠졌거나 비었을 때 | Region당 1회 | Region crop | 없음 |
| 5 | 영역 Judge `parser_v2_region_reading_judge` | OCR과 Reader 글자가 다를 때 | Region당 1회 | Region crop | 후보 1(Reader)·후보 2(OCR) |
| 6 | 표 후보 검증 `parser_v2_visual_table_verify` | 표 후보마다 | 후보당 1회 | 페이지(빨간 박스) + 확대 | 구성 Region ID·bbox·문구 |
| 7 | 표 HTML 추출 `parser_v2_visual_table_html` | 확정된 표마다 | 표당 1~2회 | 표 crop | 없음 (재시도 때만 이전 실패 사유) |
| 8 | 표 Reader `parser_v2_visual_table_reading` | 7 실패 + 참고할 기존 판독이 없을 때 | 표당 1회 | 표 crop | 없음 |
| 9 | 표 Judge `parser_v2_visual_table_reading_judge` | 7 실패 시 | 표당 1회 | 표 crop | 조립 문구 + 기존/8 판독 |
| 10 | 템플릿 선택 `ad_template_resolution` | 규칙으로 못 정한 상품만 | 상품당 1회 | **없음** | 후보 템플릿·구분값 목록·광고 텍스트 |
| 11 | 라벨링 `parser_v2_product_labels` | 템플릿이 정해진 상품마다 | 상품별 15 Region씩 | 페이지 + ID 박스, 확대 시트 | 라벨 정의·긍정/부정 예시·Region 문구 |

VLM 호출 없이 도는 판정도 있습니다. 디지털 글자 교정(`digital_anchor.py`), 결정론 표제어
라벨, 템플릿 규칙 판정, 라벨 근거 검증이 여기에 해당합니다.

## 공통 사항 (`vlm/client.py`)

- 모든 호출이 `chat_json()` 하나로 나갑니다. OpenAI 호환 `/v1/chat/completions`로 보냅니다.
  - `temperature=0`
  - 메시지는 **user 1개**(텍스트 + 이미지들)이고 system 프롬프트는 없습니다.
  - 응답은 `response_format=json_schema(strict)`로 강제합니다. 배열 길이(`minItems`/`maxItems`)와
    ID 목록(`enum`)까지 스키마에 넣어, 모든 ID를 정확히 한 번씩 받게 합니다.
- **재시도**: 실패하면 2회 더 시도합니다(총 3회, 2초·4초 대기).
  - 응답이 잘려 JSON이 깨지면 같은 요청을 그대로 다시 보내지 않고, 출력 토큰 예산을 1.6배로
    늘려(최대 16,000) 다시 묻습니다.
  - 역슬래시가 잘못 섞여 깨진 JSON은 한 번 복구를 시도합니다.
- **이미지**: `image_part()`가 비율을 유지한 채 지정 상자 안으로 **축소만** 합니다(확대하지
  않음). JPEG로 보냅니다. 호출마다 상자 크기와 품질이 다르고, 아래 각 절에 적었습니다.
  서버는 이미지를 약 1,100토큰으로 다시 줄이므로 큰 상자를 줘도 해상도가 그만큼 늘지는 않습니다.
- **스키마 맨 앞 `analysis`**: 거의 모든 스키마가 자유 서술 칸을 맨 앞에 둡니다. 모델이 설명을
  먼저 쓰고 값을 나중에 쓰게 하려는 장치입니다. 이 칸이 없으면 JSON을 닫은 뒤 말을 이어 쓰거나
  최소한의 응답만 내는 퇴행이 실측됐습니다.
- **확신도는 참고용**: 모델이 돌려주는 `confidence`는 거의 항상 최댓값입니다. 0.7 기준으로
  검수 표시를 붙이는 곳이 있지만, 이 값만으로 품질을 판단하지 않습니다.
- 개발용 캐시(`VLM_CACHE=r|p`)를 켜면 같은 요청의 응답을 재사용합니다. 기본은 꺼져 있습니다.

## 1. 문서 분류 — `vlm/client.py::classify()`

**언제**: 문서마다 1회, 첫 페이지로 부릅니다. HWP도 렌더한 첫 페이지로 부릅니다.

**입력**
- 이미지: 첫 페이지 전체(896×2400 안으로 축소, JPEG 85)
- 텍스트: 아래 프롬프트와 파일명

**프롬프트 원문**
```
당신은 금융상품 광고물 분류기입니다. 이미지를 보고 다음을 판정하세요.

1. analysis: 이미지에서 무엇이 보이는지 두 문장 이내로 먼저 서술하세요.
2. product_group: 광고하는 상품의 성격
   - 예금성 : 예금·적금·입출금 통장·지수연동예금(ELD). 수익률이 지수에
              연동된다는 사실만으로 예금 상품을 투자성으로 바꾸지 마세요.
   - 대출성 : 대출 상품
   - 카드   : 신용카드·체크카드, 카드사가 파는 장·단기 카드대출
   - 투자성 : ISA·퇴직연금·IRP·펀드·집합투자증권
   - 기타 / 판단불가
   ※ '카드대출'은 카드 상품이지 대출성이 아닙니다.
3. ad_type: 광고물 형태 — 상세페이지(세로 스크롤 웹/모바일), 안내장(인쇄물 형태), 배너, 이벤트페이지, 기타
4. product_name_shown: 특정 상품의 **고유 상품명**이 광고에 적혀 있는지
   - 노출   : "올원e적금", "NH직장인대출" 처럼 상품 이름이 보인다
   - 미노출 : 은행/카드사 브랜드만 있고 개별 상품명이 없다 (브랜드 홍보·이벤트 등)
   - 판단불가
   ※ "NH농협은행" 같은 회사명은 상품명이 아닙니다.

파일명 힌트: "{파일명}"
파일명 힌트는 강한 사전확률입니다. 이미지에서 명확히 반대되는 증거가 보일 때만 뒤집으세요.
reason 은 한 문장으로.
```

**받는 값**: `analysis`, `product_group`(enum), `ad_type`(enum), `product_name_shown`(enum),
`confidence`, `reason`

**받은 뒤**
- 파일명 키워드로 얻은 상품군(`filename_prior`)과 합칩니다. 어느 경로로 정했는지는
  `category_source`에 남깁니다.
  - `filename_and_vlm`: 둘이 일치
  - `vlm_overrode_filename`: VLM이 파일명과 다르게 판정
  - `filename_vlm_abstained`: VLM이 기타/판단불가라서 파일명을 적용
  - `filename_vlm_failed`: 호출 실패
- 이 결과는 문서 기본값입니다. 상품별 상품군은 2번에서 다시 판정하고, 템플릿 선택은 2번 결과를 우선합니다.

## 2. 페이지 맥락·상품 소유권 — `parse/semantic.py::analyze_page_ownership()`

**언제**: 페이지마다 1회. 타일로 나눠 보낸 긴 페이지는 세로(또는 가로)로 2~4개 밴드를 나눠
밴드마다 1회 부릅니다. 밴드끼리는 60~200px씩 겹치고, 각 Region은 중심이 속한 밴드에 한 번만 들어갑니다.

**입력**
- 이미지 1장: 페이지(또는 밴드)에 기존 Region을 **파란 박스 + ID**, 복구 후보를 **주황 박스 +
  ID**로 그린 것(1400×2400 안, JPEG 90)
  - 복구 후보: 어느 Region에도 들어가지 않은 OCR/PDF 줄을 묶은 것입니다.
- 텍스트: 프롬프트 + 목록
  - `- p1_r003 bbox=[x0,y0,x1,y1] layout=text text=...(700자까지)`
  - `- p1_x001 bbox=[...] text=...`
  - **`text`는 이 시점의 Region 정본**입니다. PDF는 기본값(anchor)에서 OCR 문구이고, 이전 방식에서는
    디지털 줄이었습니다. HWP는 구조·디지털 원문입니다.

**프롬프트 원문**
```
당신은 농협 금융광고 페이지 구조 판독기입니다.

이미지의 파란 박스는 기존 PaddleX Region이고 주황 박스는 OCR/PDF 줄로 만든 복구 후보입니다.
다음 작업을 한 번에 수행하세요. **이 단계에서는 라벨을 붙이지 않습니다.**

1. products: 실제 상품이 여러 개면 product_1부터 시각적 순서대로 정의하세요.
   상품마다 product_group(예금성/대출성/카드/투자성)과 상품명 노출 여부를 따로 판정하세요.
   한 광고 안에 성격이 다른 상품이 섞여 있을 수 있으므로 파일명에 끌려가지 마세요.
2. region_decisions: 아래 REGION ID를 정확히 한 번씩 반환하고 상품 소유권을 정하세요.
   회사명·로고·심의번호·연락처·공통 안내문구, 그리고 특정 상품 하나가 아니라
   광고 전체에 걸리는 유의사항은 **반드시 page_common**입니다.
   unknown은 상품 소속도 공통도 아니라고 판단될 때만 쓰는 마지막 선택지입니다.
3. recovery_decisions: 아래 CANDIDATE ID를 정확히 한 번씩 반환하세요.
   - new_region: 독립 의미 영역
   - attach_context: target_region_id의 설명·유의사항이지만 bbox는 별도 보존
   - page_common: 회사명·심의번호 등 공통 영역
   - decorative: 심의 텍스트로 쓰지 않는 순수 장식
   - needs_review: 확정 불가
4. table_areas: PaddleX가 표로 표시하지 못했지만 **하나의 심의 항목에 속하는 표**가
   보이면 그 REGION/CANDIDATE ID를 member_ids에 적으세요. 좌표는 쓰지 않습니다.
   `대출대상 | 값`, `대출한도 | 값`, `대출기간 | 값`처럼 서로 다른 심의 항목의
   나열은 하나의 표 후보로 묶지 마세요. 다른 상품 패널의 조각도 섞지 마세요.
5. missing_visible_text: 이미지에는 분명히 보이지만 REGION/CANDIDATE 목록에 전혀 없는 문구만 적으세요.

중요 규칙:
- analysis는 세 문장 이내로 쓰세요. 길면 응답이 잘립니다.
- bbox를 새로 만들지 말고 제공된 ID만 선택하세요.
- 다른 상품의 내용을 같은 product_id에 섞지 마세요.
- 표·고지·상품 설명이라는 PaddleX layout 이름은 힌트일 뿐 정답으로 믿지 마세요.
- 원문에 없는 문구를 추측하지 마세요.

페이지 크기: [W, H]
현재 이미지 범위: 페이지 전체 | 긴 페이지 y축 band 2/3, 원본 crop=[...]. product_1은 문서 전체에서 같은 상품 ID입니다.
[기존 REGION — 파란색]
- ...
[복구 CANDIDATE — 주황색]
- ...
```

**받는 값**
- `products[]`: `product_id`(product_1…), 상품명, 상품군, 상품명 노출 여부
- `region_decisions[]`: Region마다 `product_id`(product_N / page_common / unknown)와 `confidence`.
  배열 길이는 Region 수로 고정합니다.
- `recovery_decisions[]`: 후보마다 `action`, `target_region_id`, `product_id`, `confidence`, `reason`
- `table_areas[]`: `member_ids`(목록의 ID만), `note`, `confidence`
- `missing_visible_text[]`: 목록에 없는 문구, 가까운 ID, 세로 위치 비율

**받은 뒤** (`validate_ownership`, `pipeline._apply_ownership`)
- 모르는 ID와 중복은 버리고, 빠진 ID는 `unknown` + 확신도 0으로 채웁니다.
- 소유권 확신도가 0.7 미만이면 `ownership_low_confidence`, `unknown`이면 `ownership_unknown`을 붙입니다.
- 복구 후보는 `action`에 따라 새 Region이 되거나(`pN_x…`), 대상 Region의 설명으로 붙거나, 장식으로 빠집니다.
  `needs_review`거나 확신도가 0.7 미만이면 `recovery_*` 사유가 붙습니다.
- `table_areas`는 6번 표 검증의 후보가 됩니다. 모델이 이 칸에 좌표를 주면 실행마다 크게
  흔들리는 문제가 실측돼서, 좌표는 받지 않고 ID만 받습니다.
- 이 판단은 실행마다 흔들릴 수 있습니다(같은 입력에서 상품 배정·표 묶음이 달라진 사례가 있음).

## 3. 페이지 Reader — `parse/reading.py::read_page_regions()`

**언제**: 페이지마다. 2번과 같은 밴드로 나누고, 밴드 안에서 **Region 최대 20개, OCR 글자 합계
2,400자** 단위로 묶어 부릅니다. 대상은 표가 아닌 bbox 있는 Region 전부입니다.
- 제외: HWP 원본 구조 표, document-processor가 원본에서 읽은 텍스트

**입력**
- 이미지 2장 (둘 다 1400×2400 안, JPEG 90)
  1. 원본 페이지(밴드). 박스가 글자를 가리지 않도록 그림 없이 보냅니다.
  2. 같은 페이지에 **이번 묶음 Region만** 파란 박스 + ID를 그린 것
- 텍스트: 프롬프트 + `- p1_r003 bbox=[x0,y0,x1,y1]` 목록
  - **OCR 문구는 주지 않습니다**(`PARSER_V2_PAGE_READER_TEXT=off`). 주면 모델이 그대로 베껴
    Judge와의 독립성이 깨지는 사례가 있었습니다.
  - PaddleX 분류명(layout)도 주지 않습니다. `layout=image`를 받은 큰 배너를 "그림이라 글자 없음"으로
    비워 돌려준 사례가 있었습니다.

**프롬프트 원문** (Paddle 문구를 주지 않는 기본값)
```
당신은 금융광고 페이지 전사기입니다.

첫 번째 이미지는 원본 페이지이고, 두 번째 이미지는 같은 페이지에 파란 박스와 REGION ID를
그린 것입니다. 박스 위치는 두 번째 이미지로 확인하고, 글자는 가림이 없는 첫 번째 이미지에서
읽으세요.

박스는 PaddleX 레이아웃 결과이며 **정답이 아니라 위치 참고용**입니다.
- 박스가 글자를 일부만 덮거나, 서로 다른 항목을 한 박스에 섞었을 수 있습니다.

아래 REGION ID {N}개를 **모두** region_readings에 정확히 한 번씩 넣고,
각 박스 안에 실제로 보이는 글자를 이미지에서 직접 읽어 text에 적으세요.
- 해당 박스 밖의 글자는 넣지 마세요. 줄바꿈은 보이는 대로 유지하세요.
- 숫자·금리·날짜·괄호·각주 기호는 보이는 그대로 적고, 요약·설명·추측하지 마세요.
- 읽을 수 없거나 글자가 없으면 text를 빈 문자열로 두세요.
- box_issue: none(정상), cut_off(박스 경계가 글자를 자름), mixed(서로 다른 항목이
  한 박스에 섞임), no_text(박스 안에 글자 없음).
- analysis는 한 문장만 쓰세요.

페이지 크기: [W, H]
현재 이미지 범위: 페이지 전체 | 긴 페이지 y축 band 1/3, 원본 crop=[...]
- p1_r001 bbox=[...]
- ...
```

**받는 값**: `region_readings[]`. 배열 길이는 묶음 Region 수로 고정하고, 항목마다
`region_id`, `box_issue`(enum), `text`, `confidence`를 받습니다.

**받은 뒤** (`read_page`)
- 묶음 하나가 실패하면(응답 깨짐 등) 그 묶음의 Region은 결과가 없는 것으로 보고 **4번 crop
  Reader로 다시 읽습니다**(`vlm_reading.mode=region_fallback`). 다른 묶음 결과는 유지합니다.
  - 실측: 모바일 긴 캡처에서 모델이 📞 이모지를 끝없이 반복해 응답이 깨졌고, 13개 Region이 crop으로 대체됐습니다.
- 판독이 비었는데 OCR 글자·숫자가 4자 이상이면 그 Region만 crop으로 다시 읽습니다(`region_blank_recheck`).
- 그 뒤 5번 Judge 조건을 확인합니다.

## 5. 영역 Judge — `parse/reading.py::judge_region()`

**언제**: Reader 판독이 비어 있지 않고, OCR 문구와 다음 중 하나라도 다를 때 부릅니다.
- 공백을 뺀 일치도(`SequenceMatcher`)가 0.95 미만
- **공백·기호를 뺀 글자·숫자가 한 자라도 다름** (`PARSER_V2_JUDGE_TRIGGER=strict`, 기본)
  - 긴 문장의 한 글자 오독(`여신`→`연신`)은 일치도 0.95를 넘겨 이전 방식에서는 Judge 없이 통과했습니다.
  - 띄어쓰기·줄바꿈·글머리 기호만 다른 경우는 부르지 않습니다.

**입력**
- 이미지: 4번과 같은 crop(흰 여백, 확대 규칙 동일, 1400×1400, JPEG 92)
- 텍스트: 두 후보. 기본(`blind`)에서는 **어느 판독기가 만든 후보인지 숨깁니다.**

**프롬프트 원문** (기본 `PARSER_V2_JUDGE_PROMPT=blind`)
```
첨부 이미지는 광고 문서에서 잘라낸 영역 하나입니다.
아래 두 후보는 서로 다른 판독기가 만든 것이며 어느 쪽도 정답이 아닐 수 있습니다.
**이미지에 인쇄된 글자만** 기준으로 최종 텍스트를 한 글자씩 확인해 적으세요.

- 후보 1:
{Reader 판독}

- 후보 2:
{OCR 문구}

규칙:
- 금융 용어·상품명·상환방식 명칭을 더 흔하거나 올바르다고 생각되는 표현으로 바꾸지 마세요.
  이미지에 인쇄된 표기가 일반적인 용어와 달라도 인쇄된 그대로 적으세요.
- 후보끼리 다른 부분은 특히 이미지의 해당 글자를 직접 확인하세요.
- 두 후보 어디에도 없는 글자를 넣을 때는 이미지에서 분명히 보일 때만 넣으세요.
- 글자를 요약하거나 설명하지 말고 보이는 순서를 유지하세요.
- 숫자, 금리, 날짜, 괄호, 주석 기호를 임의로 고치거나 만들지 마세요.
- source는 후보 1이 맞으면 reader, 후보 2가 맞으면 parser, 고쳤으면 corrected입니다.
- analysis는 선택 이유 한 문장, text에는 최종 글자만 넣으세요.
```
출처를 숨기는 이유: 이전 프롬프트("후보 A (OCR/PDF 파서)", "후보 B (독립 VLM Reader)")는 모델이 VLM
쪽을 더 믿고, 흔한 용어(`분할상환`)를 인쇄된 표기(`할부상환`)보다 고르는 사례가 있었습니다.
이전 프롬프트는 `PARSER_V2_JUDGE_PROMPT=default`로 쓸 수 있습니다.

**받는 값**: `analysis`, `text`, `confidence`, `source`(parser / reader / corrected)

**최종 문구 선택** (`apply_reading`)
- Reader가 비었으면 OCR 문구를 유지합니다(`vlm_blank`).
- Judge 결과가 있으면 그것을 씁니다(`vlm_judge`). Judge 확신도가 0.7 미만이면 `vlm_judge_low_confidence`를 붙입니다.
- Judge가 없으면(두 후보가 같거나 Judge 실패) Reader 판독을 씁니다(`vlm_reader`).
  - Judge가 실패했는데 두 후보가 다르면 `ocr_vlm_disagreement`를 붙입니다.
  - OCR이 비었으면 `vlm_only_text`를 붙입니다.
- **HWP 원본 구조와 일치하는 Region은 VLM이 달리 읽어도 원문을 보존합니다.**
- 이전 방식(`PARSER_V2_DIGITAL_MODE=primary`)에서는 PDF 디지털 줄이 정본인 Region도 원문을
  보존하고 `digital_text_vlm_disagreement`를 붙였습니다. 기본값에서는 PDF가 이 경로를 타지 않고,
  대신 표 확인 뒤에 디지털 글자 교정을 받습니다(VLM 호출 아님, [PIPELINE_WALKTHROUGH.md](PIPELINE_WALKTHROUGH.md) 9단계).

## 6. 표 후보 검증 — `parse/visual_tables.py::_verify()`

**언제**: 표 후보마다 1회. 후보는 두 곳에서 옵니다.
- PaddleX가 `table`로 분류한 Region 하나씩(먼저 검증)
- 2번 VLM이 `table_areas`로 지목한 ID 묶음

**입력**
- 이미지 2장
  1. 페이지 전체에 후보 합집합을 **빨간 박스**로 그린 것(1200×1800 안, JPEG 86)
  2. 후보 주변(여백 24px) 확대에 구성 Region을 **파란 박스 + 번호**로 그린 것(1600×1600 안, JPEG 92)
- 텍스트: `1. p1_r010 bbox=[...] text=...(220자까지)` 목록과 후보 출처(paddle / vlm_page)

**프롬프트 원문**
```
금융광고 페이지의 표 후보가 실제로 하나의 심의 항목을 설명하는 표인지 확인하세요.

첫 이미지는 페이지 전체의 빨간 후보 위치, 둘째 이미지는 확대 화면과 파란 구성 영역입니다.
Paddle table 라벨과 페이지 VLM 후보는 가설일 뿐입니다. 구조나 문구를 추측하지 마세요.
여러 독립 심의 항목(예: 대출대상·대출한도·대출기간)의 나열, LMS 문단,
표 밖 각주를 한 표로 합치지 마세요. 한 후보에 다른 항목이 섞였다면 실제 표에
속하는 member_ids만 선택하세요. 하나의 Region 자체가 과하게 넓어 분리할 수
없으면 is_table=false로 두세요. 복잡한 중첩 표의 구조는 추정하지 마세요.
is_table은 선택한 ID들이 함께 하나의 표 심의 단위일 때만 true입니다.
문구·bbox·셀·의미 관계를 반환하지 마세요.

후보 출처: {paddle | vlm_page}
기존 영역:
1. p1_r010 bbox=[...] text=...
```

**받는 값**: `is_table`, `member_ids`(후보 ID 안에서만), `confidence`, `reason` (최대 850토큰)

**받은 뒤**: 다음을 모두 만족할 때만 표로 확정합니다.
- `is_table=true`이고 확신도 0.7 이상이며 선택된 ID가 있을 것
- 구성 Region의 상품 소유권이 하나일 것
- HWP 원본 구조 표와 겹치지 않을 것
- 단일 후보는 다른 Region과 같은 본문을 포함하지 않을 것(겹치면 `table_region_overlap`)

확정되면 여러 Region을 bbox 합집합 하나로 합치고 `kind=table`로 표시한 뒤 7번으로 넘깁니다.
검증 호출이 실패하면 `table_verification_failed`를 붙입니다.

## 7. 표 HTML 추출 — `parse/table_html.py::extract()`

**언제**: 확정된 표마다(`PARSER_V2_TABLE_FORMAT=html`, 기본). 결과가 무효면 이유를 붙여 1번 더 부릅니다.

**입력**
- 이미지: 표 bbox crop(흰 여백 규칙 동일, 2400×1800 안, JPEG 94)
- 텍스트: 아래 프롬프트. 재시도 때는 끝에 이전 실패 사유를 붙입니다.
  - "직전 응답은 행마다 칸 수(colspan 포함)가 달라 무효였습니다. rowspan/colspan을 다시 확인해 모든 행의 칸 수를 맞추세요."
  - "직전 응답은 이미지 안의 문구 일부가 빠져 무효였습니다. 표 위 제목·표 밖 문구도 이미지에 있으면 title 또는 notes에 모두 옮기세요."

**프롬프트 원문**
```
첨부 이미지는 금융광고에서 확인된 표 하나의 전체 영역입니다.
표를 HTML <table>로 옮기세요.

- 머리글 칸은 <th>, 값 칸은 <td>로 적고 행마다 <tr>을 쓰세요.
- 한 칸이 여러 행에 걸치면 rowspan, 여러 열에 걸치면 colspan을 쓰세요.
  걸친 자리에 같은 값을 반복해 적지 마세요. 모든 행의 칸 수(colspan 포함)가 같아야 합니다.
- 칸 폭 때문에 글자가 다음 줄로 넘어간 곳은 줄바꿈 없이 이어서 적으세요(단어를 쪼개지 마세요).
  칸 안에서 ①·•·※·- 처럼 새 항목이 시작되는 곳에만 <br>을 쓰세요.
- 글자·숫자·단위·기호는 보이는 그대로 적으세요.
- title은 이미지 안에 표 제목 글자가 **실제로 인쇄돼 있을 때만** 그 글자를 그대로 적고,
  없으면 빈 문자열로 두세요. 제목을 지어내지 마세요.
- 표 밖의 ※·- 로 시작하는 각주는 notes에 한 줄씩 넣으세요. 표 밖 문구를 <table> 안에 넣지 마세요.
- 표 이미지에 없는 행·열·숫자를 만들지 말고, 읽을 수 없는 곳은 추측하지 마세요.
- 속성은 rowspan, colspan만 쓰고 style·class 등은 쓰지 마세요.
- analysis에는 표 구조를 한 문장으로 설명하세요.
```

**받는 값**: `analysis`, `title`, `html`, `notes[]`, `confidence` (최대 9000토큰)

**받은 뒤 (코드가 판정)**
1. HTML을 병합이 풀린 격자로 바꿉니다.
2. 두 가지를 검사합니다.
   - **격자 검사**: 모든 행의 칸 수가 같고 빈 자리가 없을 것
   - **포함률 검사**: 원래 Region 문구 글자의 85% 이상이 결과(제목 + 표 + 각주)에 있을 것
3. 둘 다 통과하면 GFM 마크다운 표를 만들어 `selected_text`로 씁니다(`text_source=vlm_table_html`).
   - 머리글 행이 없으면 빈 머리글 행을 둡니다.
   - 행 병합은 값을 반복하고, 열 병합은 첫 칸에만 값을 둡니다.
   - 격자는 P1의 `visual_table`에 남습니다.
4. 두 번 모두 실패하면 `table_html_invalid`를 붙이고 8·9번 경로로 넘깁니다.

모델의 `confidence`는 0~1 범위를 지키지 않아서(실측 5.0) 판정에 쓰지 않습니다.

## 8·9. 표 Reader / 표 Judge — `parse/reading.py::read_visual_table()` (대체 경로)

**9. 표 Judge** — 같은 crop + 두 후보
```
첨부 이미지는 같은 표의 전체 영역입니다. 두 후보를 이미지와 대조해
최종 text를 작성하세요. 후보 A에는 OCR과 PDF 텍스트가 겹쳐 같은 숫자나 표제가
두 번 들어갈 수 있습니다. 실제 이미지에 한 번만 보이면 한 번만 적으세요.
각 행의 항목과 그 값을 같은 줄에 `항목 | 값`으로 연결하고 행마다 줄바꿈하세요.
여러 표가 나란히 있으면 각각의 제목과 대응 관계를 유지하세요.
숫자·단위·각주를 만들거나 생략하지 마세요. 확신할 수 없는 글자를 추측하지 마세요.
source는 A가 맞으면 parser, B가 맞으면 reader, 둘을 고쳤으면 corrected입니다.
analysis는 판정 이유 한 문장, text에는 최종 판독만 적으세요.

후보 A (OCR/PDF 조립):
{구성 Region 문구를 합친 것}

후보 B ({기존 영역 VLM Judge | 표 이미지 독립 판독}):
{기존 판독 또는 8번 결과}
```

**받은 뒤**: 9번 확신도가 0.7 이상이면 `항목 | 값` 줄 나열을 `selected_text`로 씁니다(`vlm_table_judge`).
- 원문에 한 번뿐인데 VLM이 반복한 긴 줄은 제거합니다.
- 확신도가 낮거나 실패하면 원래 문구를 유지하고 `table_vlm_read_low_confidence` / `table_vlm_read_failed`를 붙입니다.

## 10. 템플릿 선택 — `review/resolution.py::resolve_template()`

**언제**: 상품(product_N)마다 **먼저 규칙으로 정하고, 못 정했을 때만** 부릅니다.
- 상품군이 정해지면 후보 템플릿을 그 상품군으로 좁힙니다(19종 → 상품군별 3~7종).
- 규칙 예시
  - 대출성 + "대출모집/잔금대출" → 대출모집인
  - 대출성 + 상품명 노출/미노출 → 해당 템플릿
  - 예금성 + 미노출 → 상품명 미노출
  - 예금성 + 적금/거치식/입출식/지수연동 키워드가 **하나만** 있으면 → 그 유형
  - 카드 + 카드론 / 법인카드 / 개인카드 / 미노출 → 해당 템플릿
  - 투자성 + ISA(신탁형/일임형) / IRP / 퇴직연금 / 펀드 → 해당 템플릿
- 후보가 하나뿐이면 VLM 없이 확정합니다.
- `page_common`과 `unknown`은 이 호출을 하지 않습니다(아래 11번 참고).

**입력**: **이미지 없이 텍스트만** 보냅니다.
- 파일명
- 사전 분류: 2번에서 받은 상품별 상품군·상품명 노출 여부
  - 상품명 노출 여부는 상품명이 실제 그 상품 Region 문구에 있으면 `노출`로 교정합니다.
- 규칙 판정이 실패한 이유
- 후보 템플릿마다 `- 예금성상품-적립식: 구분값=회사명, 상품명, 가입대상, …`
- 광고 텍스트: **그 상품 소속 Region의 줄 원문**(6000자까지)
  - PDF 기본값에서는 OCR 줄이고, VLM이 고친 최종 문구가 아닙니다.
  - HWP는 구조·디지털 줄입니다.

**프롬프트 원문**
```
당신은 금융상품 광고 템플릿 선택기입니다.
문서에 실제로 광고된 상품과 상품명 노출 여부를 근거로 후보 중 정확히 하나를 고르세요.
확인할 수 없으면 판단불가를 고르세요. 구분값이 광고에 모두 보이지 않는다는 이유만으로
템플릿을 배제하지 마세요. 구분값은 광고가 따라야 하는 항목 목록입니다.

파일명: {파일명}
사전 분류: product_group='예금성', product_name_shown='노출'
규칙 판정: {규칙이 실패한 이유}

후보:
- 예금성상품-입출식: 구분값=...
- 예금성상품-적립식: 구분값=...

광고 텍스트:
{상품 Region 줄 원문}
```

**받는 값**: `analysis`, `template_id`(후보 + "판단불가"), `confidence`, `reason`

**받은 뒤**
- 판단불가면 `unresolved`가 되고, 그 상품 Region에 `template_unresolved`를 붙인 채 라벨링을 건너뜁니다.
- 확신도가 0.7 미만이면 `needs_review` 상태로 템플릿은 쓰되 검토 대상으로 남깁니다.
- 템플릿이 정해지면 그 템플릿의 구분값 목록이 11번의 **허용 라벨**이 됩니다.

## 11. 라벨링 — `parse/semantic.py::analyze_product_labels()`

**언제**: 템플릿이 정해진 상품마다, 그 상품 소속 Region을 **15개씩** 묶어 1회 부릅니다.
- 15개로 나누는 이유: 43개를 한 번에 물었더니 응답이 18,840자에서 잘렸습니다. Region당 약 440자가 나옵니다.
- 응답 배열이 비면 한 번 다시 묻습니다("직전 응답은 region_labels가 비어 무효였습니다…").
- `page_common`과 `unknown`도 따로 묶어 부릅니다. 허용 라벨은 다음과 같이 정합니다.
  - `page_common`: 상품이 하나면 그 상품 템플릿의 구분값 + 19종 공통 구분값(회사명·유의사항·심의번호).
    상품이 둘 이상이면 공통 구분값만 허용합니다.
  - `unknown`: 문서에 나온 모든 템플릿 구분값의 합집합 + 공통 구분값

**입력**
- 이미지 2장
  1. 페이지 전체에 **이번 묶음 Region만** 파란 박스 + ID(1400×2400 안, JPEG 90). 위치와 주변 문맥을 보여 주는 용도입니다.
  2. **확대 시트**: 묶음 Region을 3열 격자로 잘라 붙인 것
     - 칸 하나가 460×300이고, 각 Region 이미지는 약 448×258 안으로 줄어듭니다.
     - 칸 위에 ID를 적습니다. 1400×1600 안, JPEG 92.
     - 긴 유의사항 Region은 이 시트에서 글자가 거의 읽히지 않는 크기가 됩니다.
- 텍스트: 프롬프트 + 라벨 설명 블록 + Region 목록

**라벨 설명 블록** (허용 라벨마다 세 줄)
```
- 가입대상
  정의: 예금·적금에 가입할 수 있는 고객 조건
  긍정 예시: 개인(사업자) 또는 법인 등
  부정 예시: 유의사항에서 '가입대상은 변경될 수 있음'이라고 언급만 한 문장
- 금리
  정의: 예금·적금의 기본·적용·최고 금리 값
  긍정 예시: [방식 ①] 기본금리 연 0.00%(0000.00.00. 기준, 세전) / [방식 ②] 최고 연 0.00%(기본금리 0.00%, 0000.00.00. 기준, 세전)
  부정 예시: 대출금리 또는 금리 변동 가능성만 경고하는 유의사항
...
```
- **정의**: 코드에 고정된 `LABEL_DEFINITIONS`(30개 구분값)에서 옵니다. 없는 구분값은 "{라벨}에 해당하는 실제 값·조건"입니다.
- **긍정 예시**: 선택된 템플릿의 카탈로그(`nh_parser_fin/templates/ad_templates.json`)에서 그 구분값의 `example`을 **최대 2개, 각 180자까지** 가져옵니다.
  - 카탈로그 예시는 `0.00%` 같은 서식 예시라서, 실제 값이 아니라 문구의 형태를 보여 줍니다.
  - 템플릿에 예시가 없으면 "(템플릿 예시 없음)"을 넣습니다.
- **부정 예시**: 코드에 고정된 `LABEL_NEGATIVE_EXAMPLES`(13개 구분값)에서 옵니다. 없는 구분값은 "다른 항목에서 단어만 언급한 문장"입니다.

| 채권보전 | 대출금리 산정 예시에서 금리 계산 전제로만 언급한 담보·보증 |

**Region 목록 한 줄**
```
- p1_r005 bbox=[...] explicit_labels=['가입대상'] text=가입대상 개인(1인 1계좌) ...(700자까지)
```
- `text`는 **판독·표·디지털 교정을 모두 거친 최종 문구**입니다.
- `explicit_labels`는 코드가 줄 시작의 표제어(`가입대상`, `가입자격`, `기본금리`, `이자지급방식` 등 별칭 포함)를 결정론으로 찾은 결과입니다.

**프롬프트 원문**
```
당신은 농협 금융광고 구분값 라벨러입니다.

상품 product_1(NH올원e적금) 소속 영역입니다.   ← page_common이면 "페이지 공통 영역입니다. 특정 상품에 속하지 않는 회사명·유의사항·심의번호입니다."

허용 라벨: 회사명, 상품명, 가입대상, ...

선택된 템플릿의 라벨 정의와 예시:
{라벨 설명 블록}

아래 REGION ID {N}개를 **모두** region_labels 배열에 정확히 한 번씩
넣고, 각 Region에 실제로 들어 있는 구분값을 **모두** labels 배열에 넣으세요.

- 판정은 반드시 region_labels 배열에 넣으세요. analysis에 문장으로 적으면 무효입니다.
- analysis에는 전체 요약 한 문장만, 각 reason은 40자 이내로 쓰세요.
- 허용 라벨 중 맞는 것이 없으면 labels=[]로 두세요. 억지로 고르지 마세요.
- 각 labels 항목마다 evidence에 label과 해당 Region 원문에서 그대로 복사한 정확한
  quote를 하나씩 넣으세요. labels=[]이면 evidence=[]입니다.
- REGION 목록의 explicit_labels는 줄 시작의 명시적 표제어를 결정론적으로 찾은
  결과입니다. 해당 표제어가 실제 값을 이끄는 한 반드시 유지하세요.
- 한 Region에 가입대상과 가입금액처럼 서로 다른 구분값이 함께 있으면
  labels=["가입대상", "가입금액"]처럼 모두 반환하세요.
- 이 목록은 이미 이 상품 소속으로 확정된 영역입니다. 상품 소유권을 다시 판정하지 마세요.
- 첫 이미지는 페이지 전체의 파란 박스로 위치와 주변 문맥을 보여 줍니다.
- 두 번째 이미지는 같은 Region을 ID별로 확대한 시트입니다. **라벨은 해당 Region
  자체의 글자와 구조에 근거할 때만** 붙이세요. 다른 박스나 주변 문단에만 있는
  항목을 가져오면 안 됩니다.
- 유의사항 문장에 `대출한도`, `대출금리`라는 단어가 언급되더라도 그 문장이 해당
  항목의 실제 값을 설명하는 것이 아니면 그 라벨을 붙이지 마세요.
- 기준금리·가산금리·우대금리로 최종 대출금리를 설명하는 산정 예시 안의 대출금액,
  대출기간, 상환방식, 신용등급, 담보는 계산 전제입니다. 별도 표제어가 없는 한 해당
  Region에는 `대출금리`만 붙이고 전제 항목의 라벨은 붙이지 마세요.
- 짧은 상품 제목 Region에는 상품명 외의 페이지 구분값을 붙이지 마세요.

페이지 크기: [W, H]
{Region 목록}
```

**받는 값**: `region_labels[]`. 배열 길이는 묶음 Region 수로 고정합니다. 항목마다 다음을 받습니다.
- `region_id`
- `labels[]`: 허용 라벨 enum
- `evidence[]`: `{label, quote}`
- `confidence`, `reason`

**받은 뒤** (코드 검증 → 보완 → 제약, 순서대로)
1. **허용 라벨 확인**: 허용 목록에 없는 라벨과 중복을 버립니다.
2. **근거 검증**: 라벨마다 `quote`(공백 정규화)가 **그 Region 최종 문구 안에 실제로 있어야** 합니다.
   없으면 그 라벨을 버립니다.
3. **모순 제거**: 라벨을 붙이고 reason에 "허용라벨없음 / 해당없음 / 근거없음"이라고 쓴 응답은 라벨을 모두 지웁니다.
4. **누락 보충**: 응답에서 빠진 Region은 라벨 없음 + 확신도 0으로 채웁니다.
5. **결정론 표제어 보완**: `explicit_labels`는 VLM이 빠뜨려도 다시 붙입니다(근거 `source=explicit_heading`).
6. **제목 제약**: PaddleX 분류가 제목(doc_title/paragraph_title/title)이고 60자 이하인 Region은
   `상품명`이 있으면 `상품명`만 남깁니다.
7. **금리 산정 예시 제약**: 기준·가산·우대금리 중 두 개 이상과 "적용시" 또는 "기준,"이 있는
   문구는 `대출금리`와 명시적 표제어 라벨만 남깁니다.
8. 최종 확신도가 0.7 미만이면 `label_low_confidence`를 붙입니다. 라벨이 없는 것 자체는 검수 사유가 아닙니다.
