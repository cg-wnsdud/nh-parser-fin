# 파싱 파이프라인 상세 흐름

## 1. 입력을 공통 페이지 좌표계로 만든다

`ingest/loader.py`가 PDF, 이미지, HWP/HWPX를 페이지 이미지로 바꿉니다. PDF는 PDFium으로
렌더링하고, 선택 가능한
텍스트가 있으면 `ingest/triage.py`가 텍스트와 좌표도 읽습니다. 이 텍스트는 PaddleX OCR을
대체하는 별도 영역이 아니라, 같은 페이지 픽셀 좌표계에서 더 정확한 텍스트 후보로 쓰입니다.

HWP/HWPX 경로는 현재 HWP 개발 브랜치에서 구현·검증 중이며 아직 `main`에 병합되지 않았습니다. document-processor가
좌표 없는 문단·표 구조를 우선 읽고 실패하면 Kordoc으로 폴백합니다. 사용 가능한 로컬 백엔드가 PDF로 렌더합니다. 변환 PDF는
위의 공통 PDF 경로로 bbox를 만들며, 구조 텍스트는 실제 렌더 페이지별로 재분배해 보관합니다.

일반적인 종횡비의 페이지는 통째로 PaddleX에 보냅니다. 세로로 매우 긴 페이지는 글자 밀도가
낮은 경계를 골라 타일로 자릅니다. 각 타일 결과는 원래 페이지 좌표로 되돌리고 겹친 경계의
OCR 줄과 영역을 중복 제거합니다.

## 2. PaddleX 결과를 Region으로 조립한다

PP-StructureV3 응답의 세 목록을 함께 사용합니다.

- `layout_det_res`: 레이아웃 검출기의 원시 bbox·label·score
- `parsing_res_list`: PaddleX가 정리한 영역·본문·부분 읽기 순서
- `overall_ocr_res`: 글자 줄·인식 결과·좌표

`parse/adapters.py`는 OCR/PDF 줄 하나가 여러 Region에 중복 귀속되지 않도록 가장 알맞은 영역
하나에 배정합니다. PaddleX `block_content`가 영역 안의 줄을 충분히 포함하면 그 텍스트를
사용하고, 빠진 줄이 있으면 OCR/PDF 줄 조립본을 사용합니다. 어느 영역에도 들어가지 않은 줄은
삭제하지 않고 `unassigned_lines`와 복구 후보로 남깁니다.

## 3. VLM이 의미를 판정한다

기본 실행에서 다음 VLM 호출이 이어집니다.

1. **문서 분류**: 문서 첫 페이지 기준으로 상품군과 광고 형태를 판정합니다. 문서당 1회입니다.
2. **페이지 맥락/소유권**: 각 Region이 어느 상품 또는 페이지 공통 내용인지 판정합니다. 일반
   페이지는 1회, 긴 페이지는 2~4개 밴드로 나뉩니다. 미배정 줄 후보의 채택과 누락 표 후보 ID도
   같은 단계에서 받습니다.
3. **HWP 구조 표 확인**: 문서 구조 파서가 제공한 HWP/HTML 셀만 원본 근거로 보존합니다.
4. **HWP 구조 정렬**: HWP 입력이면 document-processor가 제공한 문단·원본 표 셀을
   렌더링 좌표의 Region에 연결합니다. 구조 경로가 실패하면 Kordoc을 보조 후보로 사용합니다.
5. **영역 판독**: VLM Reader가 영역 이미지를 전사합니다. OCR/PDF/HWP 후보와 충분히 일치하면
   그대로 확정하고, 다르면 Judge가 이미지와 두 후보를 함께 비교해 `selected_text`를 정합니다.
6. **시각 표 검증**: Paddle의 `table` 영역과 페이지 VLM이 추가로 찾은 후보를 같은
   경로로 검증합니다. 전체 페이지와 후보 확대 이미지를 보며, 실제 표에 속한 기존 Region
   ID만 고릅니다. 확인된 표는 한 Region의 `kind=table`로 표시하고 분리된 구성원은 합칩니다.
   단일 표는 해당 영역의 기존 Judge 판독을 후보로 넣어 표 전체 이미지를 다시
   판정합니다. 합쳐진 표는 최종 bbox 전체를 독립적으로 읽고 Judge가 OCR/PDF
   조립본과 대조한 결과를 선택합니다. 성공하면 P3의
   `selected_text` 출처는 `vlm`, 원래 문장은 P1 후보로 남습니다. 실패·저신뢰 결과는
   원래 문장을 유지하고 검수 사유를 붙입니다. VLM이 긴 문장을 연속 반복하고 원문
   후보에는 한 번만 있을 때만 중복 한 줄을 제거합니다. 별도 셀 행렬은 만들지 않습니다.
7. **구분값 라벨링**: 상품별 템플릿이 정해진 뒤 해당 상품 Region 묶음을 VLM에 보냅니다.
   선택된 템플릿의 정의·긍정 예시·부정 예시만 제공하고, VLM은 라벨마다 Region 원문에서
   그대로 복사한 근거 문구를 함께 반환합니다. 줄 시작의 `가입대상`, `가입금액`, `최고금리`
   같은 명시적 표제어는 결정론 규칙으로 먼저 붙입니다. 한 Region에 여러 구분값을 붙일 수
   있습니다.
따라서 호출 수는 고정값이 아닙니다. 대략 `문서 수 + 페이지 맥락 밴드 수 + 표 후보 수 +
판독 대상 묶음 수 + 상품별 라벨링 묶음 수`이며,
OCR/VLM 불일치가 있을 때 Judge 호출이 더해집니다.
실행별 실제 호출 수와 시간은 실행 결과의 통계 JSON에 기록됩니다.

## 4. 좌표와 텍스트의 책임을 나눈다

- **좌표**: PaddleX 레이아웃 bbox 또는 OCR/PDF 줄 bbox에서만 만듭니다.
- **텍스트**: OCR/PDF/HWP 구조, VLM Reader, VLM Judge 후보를 P1에 모두 남기고 하나를 최종 선택합니다.
- **의미**: VLM은 상품 소유권, 표 후보의 채택 여부, 템플릿 구분값을 판정합니다.

페이지 전체 이미지를 VLM이 함께 보므로 작은 영역만 봐서는 알기 어려운 상품 소유권과 주변
문맥을 사용할 수 있습니다. 그러나 VLM이 반환한 임의 좌표는 사용하지 않습니다. 심의 화면의
하이라이트가 원본 픽셀과 맞아야 하기 때문입니다.

## 5. 최종 ID를 정규화한다

조립 중에는 출처가 다릅니다.

- `pN_r...`: PaddleX가 만든 영역
- `pN_x...`: 미배정 OCR/PDF 줄에서 복구한 영역

이 차이는 디버깅에는 유용하지만 심의 계약에는 필요하지 않습니다. 모든 판단이 끝난 뒤 현재
페이지 배열 순서를 유지한 채 `pN_r001`, `pN_r002`, ...로 다시 번호를 붙입니다. 이 작업은
bbox, 텍스트, 라벨, `product_id`, 배열 순서를 바꾸지 않습니다. 연결 관계(`parent_id`,
`child_ids`, `related_region_id`, 채택된 표 Region ID)도 새 ID로 함께 갱신합니다.

원래 ID는 P1의 `source_region_id`와 페이지별 `region_id_map`에 남습니다. P3에는 통일된 ID만
나가므로 심의 단계는 영역 생성 방식을 알 필요 없이 `region_id` 하나로 조회할 수 있습니다.

## 6. P1에서 P3로 넘긴다

P1은 재현과 원인 분석용입니다. 다음 정보가 남습니다.

- OCR/PDF 원문 줄과 좌표, HWP 입력의 좌표 없는 구조 근거
- PaddleX 영역 관측과 내부 출처
- VLM 소유권·판독·라벨 판정
- 선택 전 텍스트 후보와 최종 선택 이유
- HWP 구조 파서가 제공한 표 셀과 시각 표 후보의 채택·거부 근거
- `needs_review`의 구체적인 사유

P3는 심의 입력용입니다. 영역마다 `region_id`, `product_id`, `bbox`, `selected_text`, `labels`,
`kind`, `needs_review`, `text_source`만 담습니다. 확인된 표에는 `kind=table`을 쓰고,
시각 표의 `selected_text`는 표 전체 이미지에 대한 VLM Judge 결과를 우선 사용합니다.
` | `는 이미지에서 판독한 항목·값의 읽기 힌트이며 확정 셀 경계는 아닙니다.
Judge 결과가 없거나 신뢰도 기준에 못 미치면 기존 문장을 보존하고 검수 대상으로 표시합니다.
후보를 채택하지 못한 이유와 HWP 원본 셀은 P1에만 남깁니다.
읽기 순서와 역색인은 P3에 넣지 않습니다. 배열 순서는 최종 페이지 Region 순서를 그대로
보존하지만, 심의 근거 참조는 순번이 아니라 `region_id`를 사용합니다.

### 표를 저장소에 적재하는 방법

P3 JSON 전체를 그대로 임베딩하거나 한 RDB 열에 중복 적재하지 않습니다.

- VectorDB에는 `selected_text`를 Region당 한 레코드로 넣고 `doc_id`, `page_no`,
  `region_id`, `product_id`, `labels`, `kind`를 메타데이터로 둡니다. 시각 표의 줄바꿈과
  ` | `는 읽기 힌트이며 확정 셀 경계로 해석하지 않습니다.
- RDB에는 P3 Region의 짧은 필드들을 저장합니다. 셀 검색·집계가 필요하면 HWP의
  원본 셀처럼 실제 구조 근거가 있는 경우에만 P1의 `table.cells`를 별도 정규화합니다.
- P1은 원본 셀, bbox, line_ref, VLM 분석, 미배치 줄을 보존하는 감사 원장으로 별도 저장합니다.

이 분리는 VLM이 추정한 셀 구조를 검색 데이터로 확정하는 일을 막습니다.
